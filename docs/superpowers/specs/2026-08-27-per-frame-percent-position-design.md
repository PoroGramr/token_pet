# TokenPet 프레임별 퍼센트 위치 설계

**작성일:** 2026-08-27  
**상태:** 사용자 설계 검토 대기

## 목표

사용자 캐릭터의 각 원본 이미지 프레임마다 Claude Code 잔여 퍼센트의 위치를 따로 저장한다. 위젯이 왕복 애니메이션을 재생할 때 숫자도 현재 이미지에 맞는 위치로 이동해 캐릭터 동작과 자연스럽게 어울리게 한다.

같은 이미지가 왕복 순서에서 다시 등장하면 동일한 위치를 쓴다.

```text
3장: 1 → 2 → 3 → 2
      A   B   C   B  # B의 퍼센트 위치는 두 번 모두 동일
```

퍼센트 글자 크기, 글꼴, 색상, 외곽선은 캐릭터 전체에서 계속 공유한다.

## 데이터 모델과 호환성

`CharacterProfile`에 선택 필드 `framePercentPositions`를 추가한다.

- 배열의 각 항목은 해당 저장 프레임 이미지의 `NormalizedPoint`(X/Y 0...1)다.
- 배열 길이는 `frameCount`와 정확히 같아야 한다.
- 각 값은 `PercentLayout`의 기존 텍스트 경계 규칙으로 표시 시 clamp한다.
- 기존 `percentPosition`은 이전 JSON을 읽기 위한 fallback으로 유지한다.

기존 저장본에 `framePercentPositions`가 없으면, 런타임과 편집 초안에서 기존 `percentPosition`을 프레임 수만큼 복제한다. 새로 저장하는 프로필은 항상 프레임별 배열을 기록하며, legacy `percentPosition`에는 첫 프레임의 위치를 함께 기록한다. schema version은 optional-field 호환이 가능하므로 1을 유지한다.

`framePercentPositions`가 있지만 길이·좌표 범위가 잘못된 프로필은 손상 프로필로 취급한다. 저장소 목록에서 제외하고, 선택돼 있었다면 기존 손상 선택 fallback에 따라 기본 캐릭터로 돌아간다.

## 프레임 순서 규칙

프레임별 위치는 이미지 자체에 붙는다. 프레임을 드래그해 순서를 바꾸면 `sourceFrames`, `displayFrames`, `framePercentPositions`를 같은 인덱스로 함께 이동한다.

기존 profile이 non-identity `frameOrder`를 갖는 경우, 편집 초안 로딩 때 이미지 배열과 위치 배열 모두 `frameOrder`를 정확히 한 번 적용해 정규화한다. 저장 시에는 기존 방식대로 identity `frameOrder`로 기록한다. 따라서 이미지 재정렬이나 재저장 뒤에도 위치가 다른 이미지로 옮겨가지 않는다.

## 런타임 렌더링

`RuntimeCharacter`는 정렬된 `frames`, `framePercentPositions`, `playbackIndices`를 함께 가진다.

1. repository는 `profile.frameOrder`로 이미지와 위치 배열을 동일하게 정렬한다.
2. `PetView`는 현재 playback index가 가리키는 프레임의 위치를 선택한다.
3. 기존 `PercentTextDrawing`과 `PercentLayout.textRect`로 텍스트를 그린다.

기본 캐릭터는 읽기 전용이므로 현재 기본 위치를 4개 프레임에 복제한다. 사용자가 등록한 캐릭터만 프레임별 위치를 편집할 수 있다.

## 관리 창 UX

프레임 타일에 선택 상태를 추가한다. 사용자는 프레임 타일을 클릭해 편집할 이미지 프레임을 고른다.

- 큰 `선택 프레임 편집` 캔버스는 선택한 한 장을 고정해서 보여 준다. 여기서 `72%`를 직접 드래그한다.
- X/Y 입력값은 선택한 프레임의 위치만 바꾼다. 제목에 `프레임 2 위치`처럼 편집 대상을 표시한다.
- 옆의 작은 `전체 애니메이션 미리보기`는 3fps 왕복 재생을 유지하며, 각 이미지에 실제 저장될 위치가 적용되는 모습을 보여 준다.
- 프레임 순서를 바꾸면 선택 인덱스는 이동한 같은 이미지로 따라간다.
- 글자 크기 슬라이더는 기존처럼 모든 프레임에 공통 적용된다.

새 캐릭터와 기존 캐릭터 모두 첫 프레임을 기본 선택한다. 이미지가 아직 3장 미만이면 위치 편집 UI는 비활성화한다.

## 오류 처리

- 프레임별 위치 배열이 이미지 수와 맞지 않으면 저장을 막고 이해 가능한 오류를 표시한다.
- 드래그와 X/Y 입력은 모두 0...1로 제한한다.
- 이미지 처리·저장 실패 시 draft, 실행 중 위젯, 선택 캐릭터는 기존 정책대로 유지한다.
- 이전 프로필의 optional 필드 누락은 오류가 아니라 자동 fallback으로 처리한다.

## 테스트

- 3/4프레임 profile JSON의 배열 round-trip 및 legacy JSON fallback
- 길이 불일치·범위 밖 프레임 좌표 검증
- non-identity `frameOrder`에서 이미지·좌표가 함께 정규화되고 재저장되는지
- 3/4프레임 왕복 재생이 해당 이미지의 위치를 반복 사용한다는 runtime mapping
- 초안 프레임 드래그가 이미지·display frame·좌표를 함께 이동하는지
- 렌더링 위치 계산과 선택 프레임 X/Y 업데이트
- 손상된 위치 배열을 가진 선택 profile의 기본 캐릭터 fallback

## 범위 제외

- 왕복의 앞·뒤 같은 이미지에 서로 다른 위치를 지정하는 기능
- 프레임별 글자 크기·색상·외곽선
- 기본 캐릭터의 프레임별 위치 편집
