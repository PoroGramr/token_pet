# TokenPet 캐릭터 관리 기능 설계

**작성일:** 2026-08-27

**상태:** 사용자 승인 완료

## 목표

사용자가 움직이는 이미지 3장 또는 4장을 하나의 캐릭터로 등록하고, 여러 캐릭터를 저장·전환할 수 있게 한다. 등록 화면에서 왕복 애니메이션을 실시간으로 미리 보고 Claude Code 5시간 한도의 남은 퍼센트 표시 위치와 글자 크기를 조절할 수 있어야 한다.

## 사용자 경험

위젯 우클릭 메뉴에 다음 항목을 추가한다.

- `캐릭터` 하위 메뉴: 저장된 캐릭터를 즉시 전환한다.
- `캐릭터 관리…`: 통합 캐릭터 관리 창을 연다.

관리 창은 왼쪽 캐릭터 목록과 오른쪽 편집 영역으로 구성한다. 기본 배터리 캐릭터는 목록에 항상 표시되며 읽기 전용이라 삭제할 수 없다. 사용자 캐릭터는 등록, 수정, 삭제할 수 있다.

편집 영역은 다음 항목을 한 화면에 제공한다.

- 캐릭터 이름
- 이미지 프레임 3장 또는 4장
- 드래그 프레임 순서 변경
- `밝은 배경 제거` 토글
- 3fps 왕복 애니메이션 미리보기
- 미리보기 위 퍼센트 직접 드래그
- 퍼센트 X/Y 좌표 미세 조정
- 퍼센트 글자 크기 조절
- `저장 및 적용`, `취소`, `캐릭터 삭제`

저장하면 선택한 캐릭터가 우측 하단 위젯에 즉시 적용된다.

## 애니메이션 규칙

지원 입력 형식은 PNG, JPG, JPEG이며 파일 선택기로 한 번에 정확히 3장 또는 4장을 선택한다. 선택 순서가 초기 프레임 순서가 되고, 편집 화면에서 드래그해 바꿀 수 있다.

왕복 순서는 프레임 수에 따라 자동 생성한다.

```text
3장: 1 → 2 → 3 → 2
4장: 1 → 2 → 3 → 4 → 3 → 2
```

재생 속도는 현재 위젯과 동일한 3fps로 고정한다. 편집기와 위젯은 같은 프레임 순서와 렌더링 설정을 사용한다.

## 퍼센트 표시 편집

편집기 미리보기에는 예시 값 `72%`를 표시한다. 사용자는 이 텍스트를 직접 드래그하고 X/Y 입력값으로 미세 조정한다.

위치는 120×120 위젯의 절대 좌표가 아니라 0~1 범위의 정규화 좌표로 저장한다. 서로 다른 이미지 크기와 Retina 배율에서도 같은 상대 위치를 유지하기 위함이다. 텍스트의 실제 경계가 위젯 밖으로 나가지 않도록 좌표를 제한한다.

글자 크기도 캐릭터 프로필에 저장한다. 편집기와 위젯은 동일한 글꼴, 테두리, 색상과 좌표 변환을 공유하여 미리보기와 실제 결과가 일치해야 한다.

글자 크기는 10~36pt 범위에서 조절한다. X/Y 좌표를 입력하거나 드래그할 때는 선택한 글자 크기의 실제 텍스트 경계를 계산해 전체 문자열이 120×120 영역 안에 남도록 제한한다.

## 데이터 모델

`CharacterProfile`은 다음 값을 가진다.

- `id`: UUID 기반 안정적 식별자
- `name`: 사용자 표시 이름
- `frameCount`: 3 또는 4
- `frameOrder`: 사용자가 정한 고유 프레임 순서
- `removesLightBackground`: 밝은 연결 배경 제거 여부
- `percentPosition`: 정규화된 X/Y 좌표
- `percentFontSize`: 퍼센트 글자 크기
- `framesPerSecond`: 현재 버전에서는 3
- `schemaVersion`: 향후 마이그레이션을 위한 버전

선택한 캐릭터 ID는 `UserDefaults`에 저장한다. 기본 캐릭터는 예약 ID를 사용하고 번들 리소스를 읽기 전용으로 참조한다.

## 파일 저장 구조

사용자 캐릭터는 다음 경로에 저장한다.

```text
~/Library/Application Support/TokenPet/Characters/
└── <UUID>/
    ├── profile.json
    ├── source-1.png
    ├── source-2.png
    ├── source-3.png
    ├── source-4.png     # 4장인 경우에만 존재
    ├── frame-1.png
    ├── frame-2.png
    ├── frame-3.png
    └── frame-4.png      # 4장인 경우에만 존재
```

`source-N.png`은 입력 이미지를 240×240으로 정규화한 배경 제거 전 원본이다. `frame-N.png`은 현재 배경 제거 설정을 적용한 위젯 표시용 파일이다. 원본과 파생 파일을 함께 보관하여 나중에 배경 제거를 끄더라도 제거된 픽셀을 복구할 수 있게 한다. 배경 제거는 이미지 바깥 테두리와 연결된 밝은 무채색 픽셀만 투명하게 만들어 캐릭터 내부의 흰색 영역을 최대한 보존한다.

프로필 저장은 같은 상위 디렉터리 안의 임시 디렉터리에 완성본을 작성하고 검증한 뒤 대상 UUID 디렉터리와 원자적으로 교체한다. 처리나 교체가 실패하면 기존 캐릭터 디렉터리를 유지한다.

## 컴포넌트 구조

### `CharacterStore`

- 기본 캐릭터와 사용자 캐릭터 목록 조회
- 프로필과 프레임 검증
- 신규 등록, 수정, 삭제의 원자적 저장
- 선택 캐릭터 조회와 기본 캐릭터 fallback
- 손상된 사용자 프로필 격리

### `CharacterEditorWindowController`

- 통합 관리 창의 AppKit 생명주기
- 캐릭터 목록, 이름, 프레임 선택과 재정렬
- 배경 제거 토글과 저장 검증
- 저장, 적용, 삭제 동작

### `CharacterAnimationView`

- 편집기와 위젯이 공유하는 프레임 재생 및 퍼센트 렌더링
- 프레임 수에 따른 왕복 순서 생성
- 정규화 좌표와 실제 화면 좌표 변환
- 편집 모드에서 퍼센트 드래그 및 경계 제한

### 기존 `PetView`와 `PetPanelController`

- `PetView`는 번들 프레임 직접 로딩 대신 선택된 `CharacterProfile`의 렌더링 모델을 받는다.
- 캐릭터 저장·선택 알림을 받으면 실행 중인 위젯이 프레임과 레이아웃을 즉시 다시 로드한다.
- `PetPanelController`는 캐릭터 선택 하위 메뉴와 관리 창 열기 동작을 제공한다.

## 데이터 흐름

1. 사용자가 `캐릭터 관리…`를 연다.
2. `CharacterStore`가 기본 캐릭터와 유효한 사용자 프로필을 로드한다.
3. 사용자가 3장 또는 4장의 이미지를 선택한다.
4. 이미지마다 240×240 `source` 프레임을 생성한다.
5. 배경 제거 설정을 적용해 `frame` 프레임을 생성한다.
6. `CharacterAnimationView`가 프레임과 `72%`를 3fps로 미리 보여준다.
7. 사용자가 프레임 순서, 배경 제거, 퍼센트 위치와 크기를 편집한다.
8. `CharacterStore`가 임시 디렉터리에 프로필과 파일을 작성·검증한 뒤 원자적으로 교체한다.
9. 선택 캐릭터 ID를 갱신하고 변경 알림을 발행한다.
10. 위젯이 새 캐릭터를 즉시 표시한다.

## 검증과 오류 처리

다음 조건을 만족하지 않으면 저장할 수 없다.

- 앞뒤 공백을 제거한 이름이 1~40자이며, 다른 사용자 캐릭터 이름과 대소문자를 무시하고 중복되지 않는다.
- 정상적으로 디코딩되는 PNG/JPG/JPEG가 정확히 3장 또는 4장이다.
- 모든 프레임 정규화와 파생 프레임 생성이 성공한다.
- 퍼센트 X/Y 좌표가 텍스트를 위젯 안에 유지하고 글자 크기가 10~36pt 범위 안에 있다.

이미지 처리나 저장이 실패하면 편집 창에 이해 가능한 오류를 표시하고 기존 캐릭터는 변경하지 않는다. 저장하지 않은 변경이 있는 상태에서 창을 닫거나 다른 캐릭터로 이동하면 변경 폐기 여부를 확인한다. 사용자 캐릭터 삭제는 확인 대화상자를 거친다. 선택된 사용자 캐릭터를 삭제하면 기본 배터리 캐릭터를 즉시 적용한다. 프로필 JSON이 손상됐거나 필수 프레임이 사라진 캐릭터는 목록에서 제외하며, 선택 캐릭터가 유효하지 않으면 기본 캐릭터로 복구한다.

## 테스트 전략

- 3장과 4장 왕복 프레임 순서 단위 테스트
- `CharacterProfile` JSON 인코딩·디코딩과 schema version 테스트
- 퍼센트 좌표 변환, 드래그 경계와 글자 크기 제한 테스트
- PNG/JPG 입력 정규화 테스트
- 배경 제거 켜기·끄기에 따른 `source` 기반 재생성 테스트
- 임시 Application Support 루트를 이용한 등록·수정·삭제·원자적 저장 테스트
- 손상된 프로필과 누락 프레임의 기본 캐릭터 fallback 테스트
- 편집기와 위젯 공유 렌더링 모델 테스트
- 앱 번들 및 기존 Claude 사용량 조회 회귀 테스트
- 실제 앱에서 등록, 미리보기, 저장, 전환, 재실행 후 유지까지 수동 통합 검증

## 범위 제외

- GIF 또는 동영상에서 프레임 자동 추출
- 캐릭터별 애니메이션 속도 변경
- 클라우드 동기화와 캐릭터 공유
- 프레임별로 서로 다른 퍼센트 위치 설정
